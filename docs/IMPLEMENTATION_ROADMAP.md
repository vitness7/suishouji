# OneLedger 实施路线图与分支地图

> 状态：生效｜基线日期：2026-07-21｜代码基线：`main@b816efd`

本文把当前对话中已经确认的产品方向、已完成能力和后续工作包整理为统一执行地图。它回答三个问题：现在已经有什么、下一步做什么、每部分应在哪个 Git 分支完成。

路线图用于安排工作，不替代具体需求卡。每个功能分支开始时，仍需在 `docs/requirements/` 下建立或更新对应需求文档，并写清范围、数据影响、界面状态与验收条件。

## 1. 产品目标

OneLedger 是一款本地优先、无需注册、离线可用的 Android 个人记账应用。核心体验是：

- 3 秒内开始记账，10 秒内完成一笔。
- 打开账本即可理解本月预算、支出与最近账单。
- 账单保存后，账户余额、预算、日历和统计保持一致。
- 默认只在设备 Room/SQLite 中保存财务数据。
- UI 使用 OneLedger 自己的蓝绿“票据轨道”语言；只借鉴成熟产品的任务流程，不复制 iCost 的页面构图、图标、文案、颜色组合或动效路径。

第一阶段不做账号、云同步、无障碍自动记账或静默 AI 入账。未来 OCR/自然语言输入必须先生成可检查草稿，再由用户确认保存。

```text
main
 └─ core-regression-gates
     └─ core-interactions
         └─ feature-state-boundaries
             ├─ account-management
             ├─ category-management
             ├─ ledger-search-filter
             ├─ data-export-import
             ├─ savings-transactions
             └─ statistics-aggregates
                 └─ v0-1-release-candidate
                     └─ v0.2 功能分支
                         └─ v1.0 发布分支
                             └─ v2.0 智能输入分支
```

图中的同级项可以按实际优先级依次实施，但每个新分支必须从当时最新且已验证的 `main` 创建。涉及 Room schema 的工作必须串行：先合并前一个 Migration 并确认新版本号，再创建下一个数据库分支，避免并行占用同一 schema 版本。

## 6. 分支执行协议

### 开始

1. 确认工作区干净并记录最新 `main` 提交。
2. 从最新 `main` 创建语义化分支，例如 `feature/account-management`。
3. 新建或更新 `docs/requirements/<feature>.md`，列出包含/不包含、页面状态、数据影响和 Given/When/Then 验收。
4. 先建立会失败的关键测试或明确可复现步骤，再实现功能。

### 开发

- 一个分支只对应上表中的一个工作包；发现无关问题时另建后续任务。
- 每次对话只要编辑了文件，就在验证后创建一次可回退的原子 commit。
- 不在功能分支顺手升级依赖、大范围格式化或改其他页面视觉。
- UI 变更同步深/浅主题和截图基准；数据库变更同步 Migration、schema JSON 与迁移测试。
- 本地 commit 是每轮交付的一部分；推送、PR 和合并在负责人确认后执行。

### 完成

1. 运行质量清单要求的 Gradle 门禁。
2. 提供用户结果、关键文件、测试证据、已知限制和 commit hash。
3. 经评审后 Squash 合并到 `main`。
4. 删除已合并的短期分支；下一项从新的 `main` 重新创建，不串接未合并分支。

## 7. 每个分支的固定交付物

```text
需求：docs/requirements/<feature>.md
代码：只包含该模块必需的实现
测试：单元测试；按风险补充 Room/UI/截图/性能测试
文档：README、架构或规范仅在事实变化时更新
提交：每次有文件编辑的对话至少一个原子 commit
汇报：完成 / 变化 / 验证 / 注意 / 文件 / commit
```

## 8. 下一分支建议

默认从 `test/core-regression-gates` 开始。当前键盘交接、日历 Pager 和数据库 v1→v3 升级已经实现，但真机自动化证据仍弱；先把这些高风险主路径固化为回归门禁，再拆状态边界和扩展账户/分类功能，可以减少后续功能把旧问题重新带回来的概率。
